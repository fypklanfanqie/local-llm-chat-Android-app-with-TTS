这段 Kotlin 的问题在 alreadyHasAssistant：它判断的是“列表里是否存在过任何 assistant 消息”， 而不是“本次回复是否已被数据库回填”。所以第 2 条回复一完成就会把 streaming 气泡删掉、又没补上 assistant， 导致回复短暂消失。
val alreadyHasAssistant = msgs.any { it.role == "assistant" && it.id != "streaming" }

只看最后一条非 streaming 消息：如果它是 assistant 且 content 与刚生成的 response 完全一致， 才说明数据库 Flow 已经抢先回填了本次回复——这时只移除 streaming 避免重复；否则原地替换为同步构建的 assistant。 这样第 2+ 条回复也不会闪没了。
